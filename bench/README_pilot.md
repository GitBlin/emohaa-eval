# Lingx 智能体 ToMBench 试跑

在本目录执行，依赖 Python 3 和 `requests`。复用上一级的 `bot_chat_client.py`，不修改原始评测代码。

```bash
# 查询当前默认凭证和用户可访问的智能体；不会发送聊天消息
python3 test_tombench_bots.py --list

# 离线生成20道题，检查输入；不会认证或访问网络
python3 test_tombench_bots.py --dry-run --limit 20

# 对一个智能体测试20道中文题，每题一次
python3 test_tombench_bots.py --bot-id 1 --limit 20

# 指定任务（文件名不带.jsonl）；可重复传 --task
python3 test_tombench_bots.py --bot-id 242 --limit 5 --task "False Belief Task"

# 英文测试
python3 test_tombench_bots.py --bot-id 1 --limit 20 --language en
```

默认 seed=42，按题目文件轮流抽样，默认20题覆盖20个数据文件；不等同于按论文8类任务分层。相同参数生成相同题目和选项顺序，便于比较智能体。每次创建独立输出目录，不覆盖历史结果。支持 `--output-dir`、`--interval` 和 `--user-id`。凭证可用 `LINGX_API_KEY`、`LINGX_API_SECRET`、`LINGX_BASE_URL`、`LINGX_USER_ID` 环境变量覆盖；默认沿用原客户端配置。

输出在 `pilot_results/bot_<ID>_<UTC时间>_<随机标识>/`：

- `metadata.json`：运行参数和已知限制，不保存密钥或令牌。
- `samples.jsonl`：题目、最终发送文本、原始答案与选项索引映射。
- `responses.jsonl`：回复原文、提取答案、对错、状态和耗时；每题立即落盘。
- `summary.json`：总体及各文件/能力的准确率、有效答案数、请求失败数、严格格式遵循率；每题更新。离线预览只生成前两个文件。

答案必须包含唯一的 `[[A]]` 等标记，且属于本题有效选项。多个不同标记或无标记均视为无效；允许解释文字但不算严格格式遵循。准确率以所有已完成尝试为分母，无效回答和请求失败均计错，同时报告有效回答上的准确率。按原始选项索引映射，不依赖选项文本相等判断；输入中的 NaN 空选项按缺失处理，支持二选一；`A. ` 标准答案规范为 `A`，保留原值。

这是连通性和行为诊断脚本：沿用原客户端的串行单条消息接口，无自动重试，不传虚构的会话字段。同一用户连续请求，服务端会话隔离尚未验证；可使用一个单独的测试用户（认证接口可能自动创建用户），但这仍不能保证题目之间隔离。智能体角色设定保留，答题要求放在用户消息中，未控制模型温度。结果不能直接当作论文设置的正式分数。ToMBench 数据仅用于评估，不用于训练。

初始验证：全部2,860道题的中英文提示词和索引映射检查通过，其中484道二选一；离线20题预览通过；模拟接口验证正常回复、无效回复和超时的保存及评分；真实列表接口返回15个可访问智能体。后续真实答题试跑见下文。

## 候选配对比较

`compare_tombench_bots.py` 在六个版本上运行完全相同的题目、提示词和选项顺序，并检查输入一致性：

| 角色 | 带 -llm 的 ID | 另一个版本 ID |
|---|---:|---:|
| 李言 | 1 | 242 |
| 怼怼大魔王 | 231 | 240 |
| 志航老师 | 1028 | 243 |

列表快照中，怼怼和志航两组各自仅 ID 和名称不同；李言两组简介和问候语相同，但定位、标签等也有差异。列表未暴露模型名、模型版本、系统提示词、工具、工作流或记忆配置，`accessType` 也没有可用的语义定义；不能根据这些字段确认 harness。用户也未确认命名约定。

```bash
# 离线验证六个版本输入一致
python3 compare_tombench_bots.py --dry-run --limit 5

# 六个版本各测试5题，共30次答题请求
python3 compare_tombench_bots.py --limit 5

# 扩展到每个版本20题，共120次答题请求
python3 compare_tombench_bots.py --limit 20
```

结果存入 `comparison_results/<UTC时间>_<随机标识>/`，包含各版本完整结果、`bots_summary.json`、`paired_summary.json` 和 `report.md`。两边答错包括无效回答及请求失败。配置未确认之前，仅称“候选版本对比”，不标注为纯模型/harness 或将差异归因为 harness 收益。正式归因需要后台确认相同模型及版本、其他生成配置，并说明两边系统提示词、记忆、工具/检索、工作流和后处理的差异；若要区分角色提示词与编排的贡献，还需增加相同模型加角色提示词的对照组。

2026-11-09 真实试跑：`comparison_results/20261109T072016Z_4ff27633/report.md`，六个版本各5题，共30次请求。李言1和242各5/5；怼怼231是角色化回复、全部无规范答案（其中一句含裸字母D）；240有1道有效且答对、4次平台生成失败；志航1028和243均进入生涯测评问卷，未回答测试题。志航后续回复表现出持续的问卷状态；不能假设题间独立。带 -llm 的版本也有角色或流程行为，不能当作已确认的纯模型。平台业务错误文本“内容生成状态失败，请稍后重试”已在评分中归入请求失败。
